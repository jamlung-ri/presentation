Three tiers, two voices: getting started with AI

A handful of copy-paste-ready examples, organized by how big a stretch each one is — and paired up to show that AI work doesn't have to mean one person, one isolated chat thread.

Same ideas, more automation

Every example below rests on the same few habits: ground the AI's output in real material, keep a consistent home for your work, stay the owner of the judgment calls, and build in a check before anything goes out. Tier 1 is a person doing all of that by hand in a chat box. Tier 3 is the same habits, with more of the legwork automated.

Not just a solo chat thread

Tiers 2 and 3 each pair an individual example with a shared team version of the same idea — a team can work off the same source together, so the AI's answers are grounded in what everyone agreed to, not just what one person happened to paste in that day.

Tier 1 Prompt-level

Zero setup. Works in a plain ChatGPT or Gemini chat box, nothing to install.

Use case

Research Synthesis → Summary

Tools: ChatGPT or Gemini  ·  Time saved: same-day turnaround on requests that used to take days
  1. Gather the question plus source material (reports, links, pasted text)
  2. Ask the AI to synthesize the sources into a comparison table, tradeoffs, and a draft recommendation
  3. Validate the findings and add your own judgment
  4. Paste the result into an email, doc, or slide outline
Why it worksThe comparison stays grounded in real sources; the recommendation stays yours.
Learning note

How to Get Better Answers — the CLEAR method

Context, Length, Examples, Audience, Refine. Weak: "Write something about our project." Strong: "Summarize the status of the project in 4 bullets for a non-technical stakeholder who needs to know what's blocked and what's next."

Prompting is a skill you build in 10 minutes of practice, not 10 hours of reading.

Tier 2 Practice-level

A small stretch. Browser only, no IDE — a free account is all it takes.

Personal use

Meeting Transcript → GitHub Issues

Tools: ChatGPT/Gemini + GitHub Issues + Projects (Kanban)
  1. Have a meeting transcript or email thread ready
  2. Ask the AI to extract action items and suggest owner/priority labels
  3. Confirm or edit before filing
  4. File as a labeled GitHub Issue on your personal Kanban board
Meeting habitVerbalize the task, owner, and due date out loud when a decision lands ("So, Name will do X by date") — the transcript already has what the AI needs, so there's far less cleanup after.
Shared team version

Same workflow, shared team repo

The exact same extraction, but filed into a shared GitHub repo instead of a personal one — turning it into a group Kanban board everyone can see and trust, instead of tasks living only in one person's notes.

Why it worksA real, structured home for tasks — now owned by the team, not just an individual.

Use case

Shared Gemini Notebook as a Team's Meeting Memory

Tools: a shared Gemini Notebook, fed with meeting transcripts  ·  no GitHub, no repo — lives inside the AI tool itself
  1. Team uploads transcripts/notes into one shared Notebook as meetings happen, building a running library
  2. Anyone asks the Notebook a question directly; it answers using only the uploaded material and cites the source
  3. Spot-check the cited source before acting on anything important
  4. Share the cited answer back in the team channel
Why it worksA shared source of truth living inside an approved AI tool itself — every answer traceable back to the meeting it came from.
Tier 3 Advanced — same ideas, automated

Where this direction can lead. Both examples run on ChatGPT Codex operating directly on a repo, not a pasted excerpt — Codex is approved, but it lives in an IDE, so this is still a bigger lift for a beginner audience than Tiers 1-2.

Use case

Live Meeting Notes

Tools: Zoom transcript + ChatGPT Codex + Markdown + a published HTML page
  1. Point the AI at the live Zoom transcript during the meeting
  2. It drafts a chronological notes doc (decisions, owners, dates) plus a condensed readout as the meeting goes
  3. Check speaker attribution and confirm decisions match what was actually agreed
  4. Publish as an HTML page on the team site; share the readout
Full stackA dedicated, consistent home for meeting records over time, a source captured automatically with zero extra meeting-time effort, and an explicit human check before anything publishes.
Use case

AI Working Directly From a Shared Team Repository

Tools: a shared GitHub repo with a structured issue template + approval workflow, plus an AI agent pointed at the whole repo — not just pasted excerpts
  1. A new question or proposed change comes in
  2. The AI reads the shared repo directly — its template, its index, its past decisions — to draft a new entry in the right format, or check if it's already been answered
  3. The team's existing approval process stays exactly as it was — AI drafts, humans still approve
  4. The new entry gets filed back into the same shared repo, extending the same source of truth
The clearest example hereThe AI reads the shared repo and writes new entries back into it — closing a loop the Tier 2 examples still leave to a person. The shared repo stays the source of truth, not any single conversation.

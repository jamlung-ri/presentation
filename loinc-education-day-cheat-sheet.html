The last topic covered was what an ontology is, told as "a tale of two dogs":

  • Start with a list of dog breeds: Pomeranian, American Eskimo dog.
  • Beside it, keep a separate hierarchy of coat types. Link both breeds to "double coat" with a relationship called has coat type.
  • Add another hierarchy, geographic origin, and another relationship: Pomeranian to Europe, American Eskimo dog to North America.

Clinical documents work the same way. Two cardiology notes (a medical student's admission evaluation and an attending's progress note) both link, through the subject matter relationship, to "cardiovascular disease," which sits under "internal medicine" in the subject matter hierarchy.

What LOINC is

TermPlain-language meaning
LOINCA universal set of codes for identifying health observations and measurements, so systems "speak the same language" when they exchange data
Coded dataHealth information recorded with standard codes instead of free text, so computers can interpret and act on it
Local codesThe in-house codes a lab or hospital already uses; these get mapped to LOINC

How data is shaped

TermPlain-language meaning
Name-value pairA piece of data split into what is being described (name, the question) and what was found (value, the answer). LOINC codes the name
Observation vs. orderAn observation is a result or finding; an order is a request for a test. A LOINC code can represent either or both
PanelA LOINC code for a group of tests ordered or reported together. Also called a battery or collection

How a code is built

TermPlain-language meaning

SystemWhere you look for it: the sample or body site, such as blood, serum, or urine
Kind of propertyWhat aspect was measured, such as mass concentration or molar concentration
Six-axis modelThe six parts that together define a LOINC concept: component, property, time, system, scale, method
Pre-coordinationPutting several things together into the meaning of one code
Post-coordinationUsing a simpler code and sending the other parts separately

Two things people get wrong

  • A LOINC code does not tell you everything. Units, reference range, interpretation, and priority travel in other parts of the message. "There's no LOINC code for what I do" often means someone expects the code to carry all of that.
  • LOINC and SNOMED CT are partners, not rivals. LOINC codes the question; when the answer is itself a code, it often comes from SNOMED CT or another terminology.

Rules of thumb

Part links tell you what a code is made of, not what kind of thing each part is. To ask "any kind of physician," you need the hierarchy as well.

Do not rely on a general-purpose AI chatbot for a complete list of codes. In the session's test it was close but both added a wrong code and missed a right one.

To find every code for something, filter by parts; do not rely on text search. Search returns near-misses. Intersecting the codes linked to the right component, property, and system parts returns exactly the set.

When searching, use LOINC's wording and check the dropdown. "Spermatozoa," not "sperm." Codes, not parts.

Do not open the part link files in Excel. Together they have over 2 million rows.

LOINC names are generated, not written. If a name reads oddly, that is the price of every name being built from parts by the same rules.

The code is the identifier; the name can change. Do not use a code's name to check that a code is correct, unless you check it against the name history file.

No code system should carry all the data. Decide what goes in the code and what goes in the data model around it. Be model-driven, not terminology-driven.

Ask "what am I actually examining?" For a heart rate, the thing examined is the rate, not the heart. Where it was taken (wrist, fetus) is the body part.

A titer is always semi-quantitative. From activity example 1, where it was the part most people hesitated on.

When a pre-coordinated code is still the right call (from the Q&A): for ordering, where one click beats three; for analytics, where one column beats three; and when the thing on the entry screen needs a name of its own.

Easily confused

  • "Property" the axis vs. "property" the column: in the part link files, the column headed "property" holds the relationship type (as component, as system...). It is not the property axis of a code.
  • A LOINC code vs. a LOINC part: a code identifies a whole observation. A part (identifier starting LP) is one building block of a code's name. Parts are not a terminology to record data with.
  • Antibody vs. antigen as the component: the test in activity example 1 looks for the patient's antibody to the organism, not the organism's antigen or the species itself.
  • A dot in the system vs. post-coordination: "body part.left" is still one pre-coordinated system. Post-coordination means sending a part separately in the message.
  • Fully specified name vs. common name vs. short name: three names for the same code. The first is for computers, the other two for people.
  • Ordinal vs. nominal: both are picked from a list. Ordinal lists have an order (mild, moderate, severe); nominal lists do not (colors).
  • Semi-quantitative vs. ordinal: a titer is a range of numbers; "2+" only tells you it is more than "1+".
  • Property vs. units: the property is the kind of quantity (substance concentration). The units (moles per volume in some specific unit) are sent in the message, never in the code.
  • How the form looks vs. how the data is stored: a screen of yes/no tick boxes does not force yes/no codes in the database. The two can be designed separately.
  • Same analyte, different method: two albumin methods usually agree, but not in every patient. Whether they count as "the same test" depends on the use case.
  • Finding in the question vs. finding in the answer: "Klebsiella pneumoniae found? yes/no" puts the organism in the question. "Bacteria identified = Klebsiella pneumoniae" puts it in the answer. LOINC prefers the second.
  • Laboratory LOINC vs. clinical LOINC: in lab, the thing measured is a substance or cell in a specimen. In clinical, it is an aspect of the patient (weight, blood pressure, a reflex).
  • "Component" and "system" across areas: the same column names mean a substance and a specimen in lab, but an examination and a body part in clinical.
  • The six axes in document codes: only component, system, and method carry meaning (type of service and kind of document; setting; subject matter and role). Property, timing, and scale are fixed values.
  • Document codes vs. observation codes: a document code names a type of document; it does not ask a question with a short answer.
  • FHIR Observation vs. OBX segment: the same job in two generations of HL7 standards (FHIR is newer, v2 is older).
  • LOINC vs. NPU: two standards for lab measurements built on the same component / system / property idea.

Acronyms

  • C-CDA: Consolidated Clinical Document Architecture, an HL7 standard for clinical documents
  • CDC: US Centers for Disease Control and Prevention
  • CDISC: Clinical Data Interchange Standards Consortium, standards for clinical research data †
  • DICOM: Digital Imaging and Communications in Medicine, the standard for medical images †
  • EHDS: European Health Data Space
  • FHIR: Fast Healthcare Interoperability Resources, the newer HL7 standard †
  • HGNC: HUGO Gene Nomenclature Committee, which assigns standard gene names
  • HPLC: high-performance liquid chromatography, a lab method †
  • HL7: Health Level Seven, the organization behind the main health messaging standards †
  • HL7 v2: the older, widely used HL7 message format †
  • ICD: International Classification of Diseases, used for billing diagnoses †
  • IUPAC: International Union of Pure and Applied Chemistry
  • LOINC: Logical Observation Identifiers Names and Codes
  • NCnc: number concentration, a LOINC property abbreviation
  • NPU: Nomenclature for Properties and Units †
  • OWL: Web Ontology Language
  • RxNorm: a US standard terminology for medications †
  • SHIELD: a US collaboration on lab data interoperability †
  • SNOMED CT: a large clinical terminology for diagnoses, findings, organisms, and more †
  • UCUM (?): Unified Code for Units of Measure, also stewarded at Regenstrief †
